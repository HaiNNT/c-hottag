A Remote Control, connector, artifact or routine request never goes out on Claude Code's own (Home) login any more, and the remote account's token is kept fresh.

## Fixed

- A request whose remote or owner account had a stale token (the daemon log said `chottag: passthrough A stale`) used to go out unchanged, on Home's own login, so after a resume a Remote Control session or connector could act as the wrong account. Now chottag waits up to 15 seconds for a refresh (and tries one, even through a backoff, when none is running, at most once a minute per account). If the account still has no usable login, chottag answers the request itself with a 503, `chottag: account A (remote) has no usable login right now; run: chottag login A`. This holds with only the `default` pool too, and when `state.json` cannot be read. It applies when a remote account is set.
- The safety net never resends a remote-class or owner-routed request on Home's own login (it did, with one pool, after a refusal and a refresh). The refusal goes back as it came, and still counts toward `chottag doctor`'s `route-drift`.

## Added

- The daemon keeps every pool's remote account's token fresh: it refreshes it when 6 minutes or less are left (Claude Code renews its token only close to expiry), once a minute at most, one at a time, and respects a failure backoff. A refresh that leaves the expiry unchanged is not repeated until the last 5 minutes. It is stopped and joined at daemon shutdown. An account that needs a login is skipped and logged once. Nothing new is written to `state.json`.

## Changed

- A claude.ai object that only Home's login can see (made before chottag, or by a `CHOTTAG_BYPASS=1` session) now gets the remote account's 403 or 404 through chottag, instead of a silent resend on Home's login. Run `chottag remote <account>` for an account that can see it, or use it from a `CHOTTAG_BYPASS=1 claude` session (see Known limitations).
- `chottag doctor`'s `route-drift` row counts a swapped request refused after its refresh and retry, whether it was resent on Home's login or, for remote, owner and pooled requests, refused as is.

- The daemon log says what happened, at most once a minute per account: `chottag: sent on Home's own login: A's token is stale (serving)` for a serving request, and `chottag: refused a remote request: A's token is stale; run `chottag login A` if it persists` for a remote or owner one, and `chottag: A's token is stale (serving): not sent on Home's own login; another pool member serves it, or it is refused` for a serving request with several pools.
- A serving request is unchanged: with only `default`, one that cannot be served still goes out unchanged.

## If Remote Control or a connector acted as the wrong account

Upgrade (`chottag update`), run `chottag daemon restart`, and reconnect Remote Control once.
