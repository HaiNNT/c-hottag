Remote Control sessions stay connected when the serving account changes or the daemon restarts: a session's account check now always gets the same account.

## Fixed

- **Remote Control dropped with "signed-in claude.ai account or organization changed on this machine."** Claude Code re-checks its own login with `POST /api/oauth/validate` and stops Remote Control when the answer names a different account from the one it pinned at start. chottag answered with whichever account was serving at that moment, so after the pool moved to another account, or right after a daemon restart, some sessions (not all) dropped and needed `/rc`. Now the first account that answers a session's validate keeps answering it for that session's life, across daemon restarts too. chottag keeps the session id, account name and email, plus a bounded list of recently dropped entries (never a token) in `run/validate-sessions.json` under `CHOTTAG_HOME`: at most 500 sessions, and one unused for 7 days is forgotten.
- A recorded account whose token is only stale is refreshed first (up to 15 seconds, like a remote request), and chottag keeps the tokens of accounts with a session used in the last day fresh even after the pool moved on, so a validate hours later is still answered by the same account.
- If that account is removed, was logged in again as another email, is not in the session's pool, has rotation off (outside the default pool), needs login, or cannot be refreshed, the serving account answers instead (never Home's login when the serving rule would not use it), and `daemon.log` gets `validate for session 1a2b3c4d moved from C to D: C needs login`. A session whose record was dropped (7 days unused, or pushed out by 500 newer sessions) is pinned again to the serving account, with a line saying so. That session may disconnect once; `/rc` brings it back.

## Notes

- A session that started before the update has no recorded account: its first validate after the update records the account serving then, which may not be the one it pinned under the old daemon, so it can drop once more (`/rc` fixes it for good). Requests that carry no session id, and every other route, are unchanged. The `claude remote-control` server's validate stays on the remote account.
- See [troubleshooting](../troubleshooting.md) for the message and [how it works](../how-it-works.md) for the rule.

## Update

`chottag update`, then the two plugin commands it prints, then `/reload-plugins`.
