First release of chottag (c-hottag): keep several Claude accounts logged in on one machine, and switch the one Claude Code uses, even mid-session, without logging out.

**Platform:** macOS is supported. Linux builds and passes CI but hasn't been used for real. The repo is private: installing needs access through a logged-in `gh` or a clone.

## What's in it

- **Accounts in their own slots.** `chottag login <name>` logs an account into its own Claude Code config dir. Your own `~/.claude` login is never changed. `logout`, `rename`, `rotate on|off` and `adopt` manage the list.
- **Per-request routing.** A local HTTPS proxy (127.0.0.1 only) picks each request's account:
  - inference goes to the **serving** account (`chottag tag`, `chottag next`);
  - claude.ai objects go to the account that owns them: remote-control sessions, artifacts, routines and connectors. New objects go to the **remote** account (`chottag remote`).
  - Switches apply to running sessions from their next request.
- **Usage and limits.** `chottag status` shows each account's 5-hour and 7-day usage and any limit, from response headers, with a light usage poll as a fallback. `next` skips limited accounts.
- **Auto-switch, on by default.** The daemon moves serving off an account nearing its limit. Each plan tier has its own switch point: pro, max5x, max20x or team, set with `chottag plan`.
  - `balanced` mode (the default) keeps you working longest and holds on to a warm prompt cache near a reset. `cache-optimize` stays until the limit.
  - A request refused at the limit is resent once on the new account.
  - `chottag auto` shows the decision, and `chottag auto off` turns it off.
- **Desktop notices** (macOS) for switches, all accounts limited, an account needing login, and route drift. `chottag notify off` turns them off.
- **Operations.** `chottag daemon start|stop|restart|logs`, `chottag doctor [--fix]`, `chottag trace on` for recording routes when Claude Code changes, and `chottag update` to keep you current from the repo you installed from (`--check`, `--version` to roll back, `--restart`). Every account, status and settings command takes `--json`; `daemon run`, `daemon logs`, `proxy`, `trace run|env|mark|summarize` and `help` don't.
- **Claude Code plugin** `claude-hottag@hottag`, whose skill drives chottag from a session.

## Install

```sh
gh api -H 'Accept: application/vnd.github.raw' repos/HaiNNT/c-hottag/contents/install.sh | sh
```

From a fork or another copy of the repo, append `-s -- --repo OWNER/NAME` to that `sh`.

`install.sh` downloads this release for your machine and checks it against `checksums.txt`, installs it under `~/.chottag/versions/`, and runs `chottag setup`. Then open a new shell. See the README's "For Claude Code" section to install the plugin too.

## Known limitations

- The proxy doesn't authenticate local callers: use a single-user machine.
- A Max plan's size isn't reported by Claude Code, so a Max account is treated as max5x until `chottag plan <name> max20x`.
- A remote-control session owned by the remote account shows the serving account's limit banner.
