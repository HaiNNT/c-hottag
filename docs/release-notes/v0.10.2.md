chottag no longer runs `claude -p` to name sessions, a refused request now records why, and a refused login is never counted as route drift.

## Changed

- **The skill and the install guide cover v0.10.** The chottag skill and [the guide for Claude Code](../for-claude-code.md) explain the unknown-owner and route-drift notices, `lostSessions` and session names, and the skill runs the read-only `chottag sessions` and `chottag names` without asking first (setting a mode still asks).

## Removed

- **`chottag names model`.** Each topic was a separate `claude -p` call, too slow to finish in time and possibly charged as extra usage. The command now exits 2 with a message and changes nothing; so does `/ct names model`. A saved `model` setting, or `CHOTTAG_NAME_SESSIONS=model`, now means `on`. chottag no longer runs a model or `claude -p` for anything.

## Fixed

- **Why a request was refused.** The `proxy.jsonl` record of a refused or failed request gains `refusedType` (the first refusal) and `errType` (the final response): Anthropic's `error.type` when it is on a fixed list, otherwise `other`, never the message or the body (a gzip body is read for it and passed on unchanged). The `login was refused` line in `daemon.log` shows it, for example `(401 authentication_error)`; the notice text is unchanged.
- **No drift for a login refusal.** A refused login on a conversation route is never recorded with `drift: true`, whatever the resend on your own login then answers. It was never counted by `route-drift`.

## Hardening

- **The retry after a 401.** It never reuses the token the upstream just refused, waits for a login renewal in flight, and tries once more when a newer token appeared meanwhile. Only a refusal of the renewed token leads to the resend and the notice, as before.
