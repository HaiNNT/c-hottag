A running session can now be put on an account you choose.

## Added

- **Move a running session.** Under `spread`, `chottag move B` puts the session it runs in on B, and `chottag move B --session 8cda` moves a live session by the start of its sid (4 characters or more; `chottag status --json` lists them under `sessions`). Ask Claude Code in a session to "move this session to B" and the plugin skill runs it. The session switches at its next request and its prompt cache starts cold on B. A moved session is *chosen*: it stays through a switch point and the cold-cache rebalance, and only a limit, rotation off, a needs-login state, its account going or leaving the session's pool, or a limit-hit retry moves it again. `B` is refused (`move_refused`) when it is out of rotation, needs a login or is limited, and when it is above a switch point unless `--force`. Under `serial` it is `move_serial`; outside a chottag session without `--session` it is `no_session`. See [`chottag move`](../commands.md#chottag-move).
- **`chosen` in `chottag status`.** `status --json` marks a moved session `chosen: true`, and the text line reads `B 1 (1 chosen)`. The daemon also publishes each session's `placed` account in `status.json`.
- **Two warnings.** `move` warns `daemon_not_running` (the move applies when a daemon starts) and `daemon_predates_move` (a daemon older than 0.10.10 ignores moves: `chottag daemon restart`).

## Changed

- **Spread places by pace.** A new session goes to the account whose 5-hour and 7-day windows its sessions use up the slowest, not the one with the most headroom: chottag measures each account's burn from every response (kept in `run/pace.json`), scores the account as `min(r5h, 3) × min(r7d, 1)` (the 5-hour term counts a refill when the reset is near, so an account about to reset does not attract every new session; burn is in plan units per hour: a max20x 5-hour window is 2000), and breaks ties by the soonest 5-hour reset, then fewer sessions, then registration order. An account about to hit its 5-hour limit is left out while another can take the session. See [Spreading sessions](../how-it-works.md#spreading-sessions-spread).
- **`chottag status` shows every serving account and the real next pick under spread.** The first line lists each account carrying live sessions with its count, `serving: A 5 · B 5   fallback: B   remote: C` (the `live sessions:` line is dropped under spread; serial is unchanged). `status --json` gains `servingAccounts`, `auto.next` (and each pool's `next`) and, per candidate, `pace`. The decision reads `spread: next session → B (5h 74% left, resets in 45m)`, and the mod's card names the same account as `next`.

## Fixed

- **`auto.burnRate` under spread** was unfed. When every pool spreads it is now the sum of the default pool's members' measured 5-hour burn; with any serial pool it stays the serial burn, which the card's and `next --pool`'s continuity read.

Run `chottag daemon restart` after updating so the daemon applies moves and places by pace.
