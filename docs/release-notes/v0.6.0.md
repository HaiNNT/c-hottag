Each `claude` session now has its own identity, and `chottag status` lists the live sessions and the account each one uses.

## Added

- Every `claude` the shim launches gets its own proxy credential,
  `chottag.default.<sid>` with a password derived from the install's secret, so the
  daemon can tell sessions apart. The older `chottag:<secret>` form still
  works, as an unidentified caller.
- `chottag status` prints `live sessions: 3 (A 2, B 1)`, the count per account,
  and `status --json` has a top-level `sessions` array: `pid`, `started`, the first
  8 characters of `sid`, `pool`, and the session's `account`, `lastSeen`,
  `requests` and `conversations`.
- `chottag statusline` shows the account this session uses, and `--json` has an
  `account` field. Before a session's first inference request, or when it cannot be
  identified, it shows the serving account as before.
- Trace records carry the first 8 characters of the session id.
- `chottag update` backs up `state.json`, and `setup` backs up your shell rc file before changing it, into `~/.chottag/backups/` (the newest 5 of each are kept). `update --json` lists the `state.json` backup as `backups`, and `setup --json` reports `rcBackup`. The `state.json` backup starts with updates run by 0.6.0 or later: before updating to 0.6.0, run `cp ~/.chottag/state.json ~/.chottag/state.json.pre-v0.6.0` once.
- The chottag mark in the README and the manual.
- `chottag status` prints `update: 0.6.0 available (run: chottag update)`, and `chottag statusline` ends with `· ↑0.6.0`, when a newer release exists. `status --json` has `update` (the check's cache) and `updates` (the two switches); `statusline --json` has `updateAvailable`.
- `chottag update --check` no longer needs `gh`: it asks GitHub's API (one request, no token) and records the answer in `status.json`.
- `chottag update --no-restart` installs and leaves the daemon running (`daemon` is `not-restarted`). An install holds `run/update.lock`; a second `chottag update` exits with `update_in_progress`.
- `chottag update --auto-check on|off` and `--auto-install on|off` set the daemon's daily update check (on by default; `CHOTTAG_NO_UPDATE_CHECK=1` also stops it) and its opt-in automatic install. `--auto-check off` also turns auto-install off.
- The daemon restarts itself onto an installed newer version once the proxy is idle (no request in flight, none started in the last 5 minutes). It looks every minute and when the Mac wakes from sleep, tries at most once an hour per version, and notifies once when a version is installed and once if the restart could not start. `chottag status` shows `daemon: running 0.6.0, installed 0.6.1 (restarts when idle, ...)` and `daemon.restartPending`; `chottag statusline` ends with ` · ⟳0.6.1` (`restartPending` in `--json`). The self-restart works with daemons from 0.6.0 on: after an update from 0.5.x, run `chottag daemon restart` once. It is on by default: `chottag update --auto-restart off` turns it off, and `update`'s deferred-restart message says the daemon restarts itself unless it is off.

## Changed

- After updating, new sessions get their own identity once the daemon restarts
  (`chottag daemon restart`); until then a `claude` started against the older
  daemon uses the `chottag:<secret>` credential and shows as unidentified.
- Restart running `claude` sessions after updating to see them listed: a session started
  before the update keeps its old credential and is shown as unidentified.
