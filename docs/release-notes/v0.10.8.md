`chottag resume` names each session it brings back, in the terminal and on Remote Control, skips a conversation that is gone, and points to conversations it never recorded. chottag now also says when Claude Code's own (Home) login is refused.

## Changed

- **`chottag resume` names each session.** Each line was `resumed <dir> in its tab`, the same for every session in one repository. It is now `resumed "<title>" (<dir>) in its tab`, with the title from the session's transcript; a session with no title shows its directory alone, as before. `failed` lines name the session the same way.

## Added

- **Home's login refused is named.** When Claude Code's own (Home) login expires and its renewal fails, every session says `Login expired · Please run /login`, and chottag's accounts cannot help: Claude Code checks its own login first. chottag now sees requests on that login answered 401 and says so: a daemon.log line, a desktop notice once the refusals last 30 seconds (at most one an hour), `Home's login was refused since 15:45: run /login in a Claude Code session` in `chottag status` (`daemon.homeLoginRefused` in `--json`), and a `home-login` row in `chottag doctor`. Run `/login` in one session.
- **Conversations chottag never recorded are listed.** After a crash, `chottag sessions` also lists, as `unrecorded`, conversations that were active in the 2 hours before the loss but were not launched through chottag's `claude` (`unrecorded[]` in `--json`), each with its `claude --resume` command. `chottag resume` does not relaunch them; it ends with how many there are.

## Fixed

- **A resumed session showed in the Claude apps as `<host>-<words>`.** Claude Code records which account owns a session's Remote Control; chottag answers that check as the serving account. On a resume, Claude Code compares the record with Home's login, and when they differ it starts a fresh Remote Control session under a neutral name and never sends the session's title. `chottag resume` now adds `--remote-control='<title>'` to a session whose transcript shows Remote Control, so the apps list it under its title. `chottag sessions` and `--print` show the same command. The conversation before the resume still does not show in the apps, and a rename after the resume does not reach them: see [known limitations](../known-limitations.md#resuming-sessions).
- **`chottag resume` relaunched a conversation that no longer exists.** A lost session whose conversation has no transcript was sent `claude --resume <id>`, which exited at once, while `resume` said `resumed`. It is now `skipped <dir>: no conversation to resume`, does not fail the command, and is marked so it does not come back (`--print` marks nothing). `chottag sessions` shows it with `missing: true` and no command.
