Auto-switch no longer moves onto an account whose login is gone, idle accounts' usage stays current, and a Claude Code message-thread 404 is no longer resent on Home's login.

## Fixed

- **A 404 on `POST /v1/messages` set off the safety net for nothing.** Claude Code 2.1.290's Message Threads continue a thread with `previous_message_id`. An account that does not hold the thread (it was created on another account, or it expired) answers 404, and Claude Code expects that: it sends the turn again as a create on its own. chottag took the 404 for a routing error. It refreshed the account's token, retried, sent the turn again on Home's own login (so it could run on Home's quota), counted route drift and showed a "route drift" notice, adding about 4 seconds to the turn. Now that 404 goes back to Claude Code unchanged, with none of those steps, and the `proxy.jsonl` record gets `passed404: true` so the cases stay countable.

- **Auto-switch moved onto an account with no login.** An idle account's login could vanish, for example when its refresh token was refused, and nothing noticed, so a later switch went to it and requests went out on Home's own login until you ran `chottag login`. Now a usage poll, a refresh or the warm pass that finds no login marks the account `needs-login`, posts one notice and stops polling it. Auto-switch never switches onto it, and a limit switch takes the next candidate. The notice fires again if the account recovers and later loses its login again.
- **Every rotating account's token is kept warm,** not only the serving, remote and validate-session ones. The daemon still refreshes a token only when about 6 minutes are left.
- **Auto-switch checks its target before a swap.**
  - A stale token is refreshed first. A limit switch waits up to 15 s for it, else takes the next candidate.
  - An old usage reading is polled first, bounded at 10 s. If that poll fails on a limit switch, it switches on the old reading rather than leave you on a limited account.
  - These waits are 25 s in all. They never hold up responses, and they end when the client hangs up.
  - A limit the daemon sees on its own takes the next ready candidate instead of waiting.
- **Idle accounts' usage no longer goes stale.**
  - An idle account is polled about every 30 minutes. A rotation-off account, such as the remote, is polled every 2 hours.
  - A failed start poll joins that schedule.
  - On a 429 the poller honours `Retry-After`, else backs off 60 then 120 minutes. A poll before a switch never overrides that.

## Changed

- `chottag status` shows a reading older than 10 minutes with its age, as in `45% (2h ago)`, instead of `unknown`. A window that has reset since the reading shows `unknown (reset since)`. `--json` keeps `stale: true` and `usage.updatedAt`.
- Auto-switch sorts readings into three ages:
  - fresh, under 10 minutes: the only age that can make the serving account leave;
  - recent, under 45 minutes: trusted when choosing a target;
  - old: ranked after recent ones, and polled before it is chosen.

## Notes

- Only a 404 on `POST /v1/messages` changes. A 401 or 403 there still gets the refresh and the notice about the account's login, and a 404 on an object or remote route, or on any other route, still counts as route drift.
- See [how it works](../how-it-works.md) and [troubleshooting](../troubleshooting.md).

## Update

`chottag update`, then the two plugin commands it prints, then `/reload-plugins`.
