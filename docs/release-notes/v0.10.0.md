`chottag sessions` and `chottag resume` bring back the Claude Code sessions that were open when cmux quit or the Mac crashed, and sessions now get useful names automatically. Unknown claude.ai objects are opened through the right account instead of raising a false route-drift notice, and `chottag status` reads more calmly.

## Added

- **`chottag sessions`.** Lists the sessions lost together at the last crash or cmux quit, each with the command that resumes it. `--all` lists every recorded session. A session you left with `/exit` is not lost.
- **`chottag resume`.** Relaunches the lost sessions, each in its own directory and pool: in its own cmux tab if that is idle, else a new tab in the same workspace, else a new workspace. Without cmux it prints the command. `--pick` chooses which, `--print` only prints and marks nothing. Running it twice is safe.
- **A journal.** The shim records each session it launches (directory, pool, cmux tab, and the Claude Code session id it uses now, which follows `/clear` and `/resume`; for a session started with `claude --resume X`, the id X, because that is the conversation it keeps writing) in `~/.chottag/sessions/`, for 7 days, with no tokens. A session id is used only if it is a canonical UUID.
- **A status hint.** `chottag status` says `2 sessions were lost at 18:01: chottag resume` while a batch is waiting, and `--json` has `lostSessions`.
- **Owner discovery.** When chottag does not know an object's owner (an artifact made on claude.ai, say) and the `remote` account is refused with a 403 or 404, a `GET` or `HEAD` now tries the other accounts of the session's pool once, up to 8, sends back the first answer that is not a refusal, and records that account as the owner only when its answer succeeds (a 429 or 5xx is sent back but not recorded). Later requests go straight to it. The daemon log says `chottag: owner of artifact <hash> found: B (A answered 404)`.
- **Session names.** With the chottag plugin, `chottag name-session` (a `UserPromptSubmit` hook) names each session at its first prompt after its branch (`feat/m12-owner-discovery` → `m12-owner-discovery`), or `<folder> HH:MM` on `main` or outside git, then `<branch> · <title>` once Claude Code has generated the session's title. A session you named yourself keeps your name. The name shows in Claude Code's agent view, the prompt bar and `claude --resume <name>`. Without the plugin, add the hook to your `settings.json` ([resume.md](../resume.md#session-names)).
- **`chottag names [on|model|off]`.** Shows or sets session naming (`on` by default). `model` also asks Claude Code (Haiku, with no tools) for a short topic at the first prompt of a session with no branch, so the name is `<folder> · <topic>`; any error or a 4 second timeout falls back to `<folder> HH:MM`. `chottag status` shows the mode when it is not `on`, and `/ct names` sets it from Claude Code. `CHOTTAG_NAME_SESSIONS` overrides it for one shell.
- **Titles in the session list.** `chottag sessions` and `chottag resume --pick` show a `TITLE` column, and `--json` has `title`. chottag reads only the `ai-title` and `custom-title` records of a transcript and never logs or stores a title.

## Changed

- **A calmer status table.** A usage cell shows its reading's age (`45% (2h ago)`) only when the reading is older than the account's poll interval plus 15 minutes (45 minutes, or 2 hours 15 minutes for a rotation-off account). The `↻` reset shows time left only under 5 hours (`42m`, `2h41m`), then a clock time: `23:59`, `Thu 08:00`, `Oct 9 18:00`. `STATE` no longer prints `-`: it is `ok`, `stale` (reading older than that window) or `no reading` (never read). `--json` is unchanged, and so is the status line.

## Fixed

- A refused request for an object whose owner chottag does not know is no longer reported as route drift. It no longer waits for a token refresh that cannot help. If no account of the pool can open it, you get one `chottag: an artifact's owner is unknown` notice per account per hour, and chottag does not try that object again for an hour. The route-drift notice now reads "A swapped request was refused even after a retry", since a refused request is not always resent.

## Notes

- Only sessions launched through chottag's `claude` are known, and a session moved with `/cd` comes back in its launch directory.
- If you use cmux's own agent restore, turn off `terminal.autoResumeAgentSessions` so the two do not both resume a session. `chottag resume` usually skips a session cmux already brought back: that works only when cmux's resume goes through chottag's `claude`.
- A tab you closed while claude ran counts as lost for 24 hours (a session lost longer ago is only in `sessions --all`).
- The session id is recorded up to 15 seconds late, so a `/clear` just before a crash resumes the conversation from before it.
- After a reboot, sessions from before it are always treated as lost.
- If cmux is there but `cmux top` fails, `chottag resume` prints the commands and marks nothing. Only one `chottag resume` runs at a time.
- A session is named from its first prompt, by branch only; the title arrives at a later prompt. The transcript format is internal to Claude Code.
- See [Getting sessions back after a crash](../resume.md).
