Pools: separate sets of accounts, each with its own serving account, remote account and policy, picked per session with `CHOTTAG_POOL=work claude`. The README now recommends letting Claude Code install and set up chottag.

## Added

- `chottag pool` lists the pools, and `pool add NAME`, `pool join ACCOUNT POOL`, `pool leave ACCOUNT POOL` and `pool rm NAME` change them (`bad_pool`, `pool_exists`, `pool_not_empty`, `pool_default`, `no_pool`, `last_pool`, `pool_ambiguous`, `not_in_pool`). An account can be in several pools. `default` always exists and is what `state.json` held before: your install is one `default` pool holding every account until you add another.
- A session picks its pool at launch: `CHOTTAG_POOL=work claude`, or an alias such as `alias cwork='CHOTTAG_POOL=work claude'` that you add to your rc file yourself. Unset means `default`. A name that is not a pool stops the launch with `chottag: no pool named "x" (chottag pool lists them)` and exit 2; it never falls back to `default`.
- A session is only ever served by accounts in its pool. Each pool has its own serving account, remote account, policy and pin; new claude.ai objects are created as the pool's remote account, and an existing object still goes to its owner. `serial` pools auto-switch on their own, `spread` pools place sessions among their own members, and `chottag login NAME --pool P`, `tag`, `next`, `remote` and `policy` take `--pool`.
- **A pool that cannot serve a request fails closed.** With more than one pool, a request its pool cannot serve (no serving account, every member out of rotation, a login needed) is answered by chottag itself with a 503 that names the pool, and Claude Code retries it. It never goes out on Home's own login, which could belong to another pool. With only `default`, nothing changes.
- Sharing an account between pools warns (`shared_account`): its usage limit is shared, so under `spread` the pools' sessions compete for it, and under `serial` they use up its 5-hour window together. `pool join` and `policy spread` print it.
- `chottag status` adds a `POOLS` column and a line per pool once there is more than one, with each pool's serving, remote, policy, live sessions, last decision and last switch, and `(B shared with personal)` for a shared account. `status --json` has `pools[]`, `pools` and `shared` on each account, `auto.pools` and a `pool` on each session; with only `default` the document is unchanged.
- `chottag statusline` shows `[work]` after the account for a session outside `default` (`pool` in `--json`), and its `n/m ok` counts the session's pool.
- Notices name the pool when there is more than one (`chottag: work: switched to C`), and each pool keeps its own "no account to switch to" episode.
- `chottag doctor`'s `roles` row checks every pool (a pool's roles name its own members) and warns when a pool's members are all out of rotation.
- Pools need a 0.8.0 daemon. `pool add` refuses (`daemon_predates_pools`, exit 2) while a daemon older than 0.8.0, or one reporting no version, runs: it cannot read a version 2 `state.json`, and could not restart itself onto 0.8.0 either. Run `chottag daemon restart` first. `pool join` warns with the same code. Once a pool exists, the shim also refuses every session (`default` included) against such a daemon, exit 2: `the running daemon (0.7.1) predates pools, so a "work" session would not stay in its pool; run: chottag daemon restart`. With no extra pool nothing changes.
- The README's comparison table gains two columns, spreading sessions over accounts and separate account pools, sourced and dated in `docs/comparison.md`.
- The agent install guide asks "Do you keep work and personal accounts apart?" (question 7), creates the pools and joins the accounts the user names, tells the user the shared-account down-side before a second join, and gives the aliases without editing the rc file. The plugin skill covers pools, the 503, `shared_account` and `daemon_predates_pools`.

## Changed

- `state.json` is written as `"version": 2` while a pool other than `default` exists, and as version 1 otherwise, so an older chottag refuses a file with pools instead of serving every account from `default`. A file with no extra pool is byte for byte what it was.
- The README now recommends letting Claude Code install and set up chottag: ask it "Install and set up chottag for me" in any session, and it follows the agent guide.

## Upgrading and rolling back

- After `chottag update`, run `chottag daemon restart` before `chottag pool add`: a daemon from before 0.8.0 cannot read what pools write.
- `chottag update --version` below 0.8.0 is refused while a pool other than `default` exists (`pools_block_rollback`, exit 2). Take the extra pools out first (`pool leave`, then `pool rm`); removing the last one writes `state.json` back as version 1.
