A connector shared by several accounts now goes to the session pool's remote account when that account listed it.

## Fixed

- **A shared connector stays on the first account that listed it.** A first-party connector has the same id in every account. chottag recorded only the first account to list it, so every call to that connector went there, even in a session whose remote account had just listed the same id, and an artifact made through it landed in the wrong account. chottag now remembers every account that listed a connector, and a call goes to the session pool's remote account when that account listed the id, otherwise to the account that listed it first. An old `owners.json` entry heals the next time the remote account lists its connectors, with no manual step. `chottag own connector ID ACCOUNT` still pins an account, and the pin wins over the remote account. Other objects (artifacts, sessions, environments) keep their first owner. `chottag own connector ID` (no account) now also lists the accounts that listed the id (`listers` in `--json`).

## Notes

- **Rolling back.** Going back to 0.10.2 or older drops the `chottag own` pins on connectors (the old code does not know them), and the old `chottag doctor` counts more entries per account, because of the extra listing rows.
