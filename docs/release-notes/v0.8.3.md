`claude auth ...` and `claude setup-token` now skip chottag by themselves.

## Changed

- `claude auth login`, `auth logout`, `auth status` and the other `auth` subcommands, and `claude setup-token`, run the real Claude Code directly, without `CHOTTAG_BYPASS=1`. The shim recognises the subcommand (`auth` or `setup-token` as the first argument, matched exactly; a flag before it, as in `claude --debug auth login`, keeps the normal path), does not read `state.json`, start the daemon or register a session, and removes chottag's own `HTTPS_PROXY` from the environment. A proxy of your own and `NODE_EXTRA_CA_CERTS` are kept. Before, such a command went through the proxy, where a request with no rule could carry a chottag account's token and make Home record the wrong email or organisation.
- A prompt that mentions the word (`claude "auth flow"`, `claude -p auth`) is unchanged. `/login` typed inside a session is still invisible to the shim: start that session with `CHOTTAG_BYPASS=1 claude`.
