Security hardening: the proxy now authenticates its callers, a certificate
mix-up inside a tunnel is refused, the local CA is constrained to Anthropic's
own domains, releases carry build attestations, and this project now has a
`SECURITY.md`.


v0.3.0 was never released, so this release also carries its changes
(`chottag update`, `install.sh --repo`, the daemon version warning); see
[v0.3.0](v0.3.0.md).
## What's new

- **The proxy requires a per-install secret.** The `claude` shim puts it in
  `HTTPS_PROXY`'s userinfo, and the daemon requires it before it will MITM an
  intercepted `CONNECT` (`api.anthropic.com`, `mcp-proxy.anthropic.com`) or
  forward an absolute-form request. A caller without it gets `407 Proxy
  Authentication Required`. A blind tunnel to any other host stays
  unauthenticated, since it can never swap a token — except when the daemon
  itself is chained through an upstream proxy that carries its own
  credentials, in which case that tunnel needs the secret too.
- **The shim verifies the daemon** before handing it the secret: a fresh
  health challenge, an HMAC proof bound to both the nonce and the port the
  daemon is actually listening on, proves the listener is this install's own
  daemon, not something else that happened to be listening there — including
  a same-secret listener on a different port relaying the challenge.
- **The tunnel Host check (421).** Inside an intercepted `CONNECT` tunnel, a
  request whose `Host` differs from the tunnel's own target is refused with
  `421 Misdirected Request`, instead of being forwarded with a swapped token
  under a `Host` the client chose.
- **The local CA is name-constrained.** A CA chottag creates from v0.4.0 on
  is limited to `anthropic.com`, `claude.ai` and `claude.com`, and excludes
  every IP address; a leaf is only ever minted for the host a `CONNECT`
  actually targeted. `chottag doctor` also now checks `ca.key`'s permissions
  and reports a pre-v0.4.0, unconstrained CA as an informational row.
- **Releases from the public repo carry a build attestation.** `chottag
  update` and `install.sh` verify it, alongside the existing checksum, and
  fail closed if verification doesn't succeed.
- **`SECURITY.md`.** A disclosure policy through GitHub private
  vulnerability reporting, supported versions, and a summary of the threat
  model. The README's `## Security` section now links to it.
- Smaller hardening: the daemon runs from a fixed working directory instead
  of inheriting whatever directory started it; the plugin skill
  pre-approves only read-only commands and everyday account switches
  (`tag`, `next`, `remote`, …); anything that logs in or out, installs,
  repairs or renames prompts; the health endpoint answers loopback,
  `Origin`-less callers only.
- **Fixed:** the daemon could miss a `chottag own` reassignment on Linux. A
  rewrite of the owners file at the same size, within the same file-clock
  tick as the daemon's own last write, looked unchanged. The daemon then
  kept routing that object to the old account until the file changed
  again. The daemon now also notices that the file was replaced.

## Renamed to c-hottag

The project, its repo and its Go module are now c-hottag:

- **The module is `github.com/HaiNNT/c-hottag`.** Once the repo is public,
  `go install github.com/HaiNNT/c-hottag/cmd/chottag@latest` installs the
  CLI; a `go install` or an import pinned to the previous module path needs
  updating.
- **The default repo is `HaiNNT/c-hottag`.** `install.sh` and `chottag
  update` now default to it. Any script, bookmark or pinned `install.json`
  that names the old repo stops working: GitHub only redirects the old
  name, and from v0.4.0 on `chottag update` and `install.sh` refuse a
  redirected repo ("moved to …; run … `--repo HaiNNT/c-hottag`"), private
  repos included — the check runs before privacy is even known. Point
  them at the new name.
- **The display name is c-hottag** everywhere a human reads it — the
  README, the plugin and marketplace descriptions, SKILL.md and the
  header of `install.sh`.
- **The plugin and skill ids are unchanged** (`claude-hottag@hottag`,
  marketplace `hottag`, skill `hottag`): renaming them would break every
  existing install, so an update never asks you to reinstall the plugin.
- **A CA chottag creates from this version on has `Organization: c-hottag`**
  instead of the old name; an existing CA keeps its own certificate as is.

## Upgrade note

Once the daemon restarts on this version, a Claude Code session that was
started before the restart gets a 407 Proxy Authentication Required
response whose text says to restart the session, on its next request,
because it is still holding the old, unauthenticated `HTTPS_PROXY`.
**Restart every running session** after updating.

- `chottag update` restarts the daemon automatically only when no session is
  currently running; otherwise it reports the restart as deferred and you
  run `chottag daemon restart` yourself once you're ready.
- Rolling back below v0.4.0 (`chottag update --version <older>`) also needs
  `chottag daemon restart` afterwards, for the same reason in reverse.
- This version also refuses to start against a `ca.key` a group or other
  can read, or a `ca/` a group or other can write — a real hazard for an
  install restored from a loose-permission backup. If `claude` won't start
  after updating, run `chottag doctor --fix`; the error it prints names
  exactly what to change.
