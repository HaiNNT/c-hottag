Requests that act on an artifact by id now follow the artifact's owner.

## Fixed

- **Artifact action routes follow the artifact.** A request such as `GET /api/frame/comments/<id>` or `POST /api/frame/versions/<id>/restore` named its artifact in the second path segment, but chottag took the action word as the artifact and found no owner, so the request could go to the wrong account and be refused with a 403. It now looks up the owner of `<id>`. Routes with the id first (`/api/frame/<id>`) and the deploy, track, types, sync and read routes are unchanged.
