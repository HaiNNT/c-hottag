`chottag update` now says what is new in the release you are getting, and reminds you (or your Claude Code) to update the Claude Code plugin too. The status card also gets a line of space above it. A refused login on a conversation request gets its own notice instead of "route drift", and `daemon.log` lines carry the time.

## Added

- **What's new.** `chottag update` and `chottag update --check` end with a short summary: for each release newer than the one you ran, up to the one found or installed (at most 5, newest first), its lead paragraph from the release notes (about 400 characters at most) and its link. `--json` has the same as `whatsNew` (`version`, `summary`, `url`). It costs one more GitHub API request through the same proxy as the check; if that fails, only the summary is left out.
- **The plugin step.** After an install, and with `--check` when a newer release exists, `update` prints how to bring the plugin to the same release: `claude plugin marketplace update c-hottag`, `claude plugin update chottag@c-hottag`, then `/reload-plugins` in each open Claude Code session (`plugin` in `--json`: `commands`, `note`). chottag never runs `claude` itself. When you ask your Claude Code to update chottag, the skill has it relay the summary, ask whether to update the plugin too, and run the two commands on a yes.
- **The mod notices a stale plugin.** It carries its own version. When `chottag version` is newer, it shows one toast per version, and the card gains `plugin 0.9.0 · chottag 0.9.1: update the plugin`.

## Fixed

- The status card has one empty line above it: it sat right under the output above, for example `/reload-plugins`'s.
- A refused conversation request is no longer reported as route drift. Since this release the `route-drift` count, `chottag doctor`'s `route-drift` row and the "route drift" desktop notice are for requests about a claude.ai object (Remote Control, a connector, an artifact, a routine), for routes chottag's table does not list, and for any 404. When a request chottag sent as account C to `/v1/messages` or `POST /api/oauth/validate` is refused with a 401 or 403 even after a refresh and retry, you now get its own notice, "chottag: C's login was refused (401)", at most once an hour per account (and again if C answers fine at least 5 minutes after the last notice), telling you the request went out on your own (Home) login and to run `chottag login C` if it repeats. The daemon log gets a line for each one (account, status, method and path, never a token or a body), and `proxy.jsonl` has a new `refused` field with the first refused status, beside `drift`.
- Every `daemon.log` line now starts with the local time (`2006-01-02 15:04:05`), so `chottag daemon logs` shows when each thing happened.
- A request that is refused while its account's token refresh is running, or within 30 seconds of one that renewed the token, now waits for that refresh and retries with the new token instead of going out on Home's login.

## Notes

- A rollback (`chottag update --version`) installs an older release and prints neither block.
- `scripts/release bump` now sets the mod's version along with `plugin.json`'s, and a test keeps them equal.

## Update

`chottag update`, then the two plugin commands it prints, then `/reload-plugins`.
